# Incident response
State observable symptoms; avoid speculative fixes; inspect host health, disk, memory, CPU, network, systemd/Docker and logs; determine blast radius; stabilize least-destructively; preserve data/evidence; validate dependencies and replication; confirm recovery; document root cause/best-supported hypothesis and follow-ups. Never wipe/reset state as first-line troubleshooting.
