# Documentation rules

- Distinguish current implementation, planned architecture, examples, and future work.
- Never imply a service is deployed/validated when it is only planned.
- Keep diagrams consistent with inventory and architecture docs.
- Operational docs include validation and recovery, not only installation.
- Prefer concise command blocks with intent and expected outcome.
- Update roadmap/status when implementation state changes materially.
