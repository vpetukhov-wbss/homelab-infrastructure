# Secrets management

> As deployed on **2026-11-21**. HashiCorp Vault is running but **not initialised**, so
> today the source of truth for secrets is **ansible-vault** on the controller.

## Where every secret lives

|---|---|---|---|
| Service passwords: PostgreSQL superuser and replicator, Redis/Sentinel, RabbitMQ. Also the backup archive passphrase | `inventory/group_vars/homelab/db_secrets.yml` | ansible-vault (homelab password) | the recovery bundle |
| sudo (become) password | `inventory/group_vars/homelab/vault.yml` | ansible-vault | the recovery bundle |

| Controller SSH key (`~/.ssh/homelab-controller`) | the controller, mode 600 | file permissions | the recovery bundle |

| Rendered service credentials | compose/config files under `~/stacks/` on each node (0600 or 0640) | file permissions | Ansible re-renders them |
| Backup passphrase and credentials on node1 | `/etc/homelab/` | root only | Ansible, from ansible-vault |

An older copy of the two ansible-vault files sits in `~/homelab/inventory/`. The re-key
script below keeps it on the same password.

## One password

The **homelab password** opens every ansible-vault file and the recovery bundle. The
owner chooses it.

`scripts/set-homelab-password.sh` re-keys everything to a new one:

- it re-keys copies first and proves each one decrypts to identical bytes;
- only then does it swap the originals in;
- if anything fails, nothing changes.

The password never goes on the installer stick or into the repository.

## The recovery bundle

`scripts/make-recovery-bundle.sh` writes `~/homelab-recovery/homelab-recovery-*.tar.gpg`,
encrypted with AES-256 under the homelab password. It contains:

- the SSH keys and the vault password;
- the repository, with full history and the git-ignored inventory and secrets;
- the WireGuard backups;
- Claude Code's project memory.

The node installer stick carries it, and `sudo homelab-restore` unpacks it. Recovery by
hand is in [`runbooks/controller-recovery.md`](../runbooks/controller-recovery.md). Keep
copies off the controller, and never in `/tmp`: on Ubuntu it is tmpfs, which is how the
2026-11-20 bundle was lost.

## Rules

- **Never commit** any of the following; `.gitignore` covers the known paths as a
  safety net:
  - passwords, tokens or keys;
  - decrypted ansible-vault files;
  - the vault password file;
  - the recovery bundle;
  - the real inventory;
  - Vault init output;
  - installer build output.
- **Never put a secret where it can leak.** It must not appear on a command line (use
  `REDISCLI_AUTH`, `--passphrase-file`, env or stdin) or in Ansible output (`no_log`).
- **Generate private keys where they are used.** Distribute only public keys.
- **No unencrypted copies.** A secret that leaves its machine travels encrypted: an
  ansible-vault file, the gpg bundle or the encrypted backup.

## If a secret leaks

1. Revoke or rotate it immediately.
2. Replace the credentials it protected.
3. Remove it from the current tree.
4. Decide whether the repository history must be rewritten.
5. Check logs for use of the secret.
6. Add a check that makes the same mistake harder to repeat.
